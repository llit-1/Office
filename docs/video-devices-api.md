# API приставок (приложение com.example.video)

Базовый путь: `/api/video-device`. Все запросы — `GET` с заголовком `X-Device-Key: <ключ>`.

Ключ задаётся на сервере в `VideoDevices:DeviceApiKey` (`appsettings.Local.json`, не в git, минимум 32 символа)
и вшивается в APK при сборке. Пока ключ не задан, API отвечает `503`; неверный ключ — `401`.

Приставка определяется по своему IP: тот же адрес, что указан в админке (`10.x.x.x`). Порт — только `8080`
(порт приложения на приставке); другие порты не принимаются ни здесь, ни в админке.

| Запрос | Ответ |
|---|---|
| `config?ip=10.140.54.60:8080` | `200` — настройки, `404` с `"code": "device_not_registered"` — приставка не зарегистрирована, `400` — некорректный IP |
| `music` | список музыки из папки `Музыка` |
| `ads?ip=…` | реклама: своя папка приставки или общая `Реклама` |
| `videos/{имя файла}` | видеофайл с `ETag` и `Last-Modified`, поддерживает `Range` + `If-Range` (докачка) |
| `audio?path=…` | аудиофайл; ссылку брать из `music`/`ads`, путь не собирать самому |
| `apk?name=2.0.apk` | APK из корня папки ВидеоТВ — для обновления приставки без ADB (команда `update`) |
| `POST heartbeat` | сигнал «я на связи» с состоянием приставки, раз в 2 минуты (см. ниже) |

Файл, который сейчас копируется на шару (открыт кем-то на запись), не отдаётся: `503` с `Retry-After: 60`.
Видео, изменённое меньше `VideoDevices:StableFileAgeSeconds` секунд назад (по умолчанию 60) или открытое на запись,
в `config` идёт с `available: false`; такие же свежие аудиофайлы не попадают в `music`/`ads` до следующей синхронизации.
Списки `music`/`ads` кэшируются на 60 секунд. JSON-ответы этого API сжимаются (gzip/brotli), медиа — нет.

**Докачка.** Приложение хранит недокачанное в `<имя>.part`, а `ETag` — в `<имя>.part.etag`. После обрыва
шлёт `Range: bytes=<сколько есть>-` и `If-Range: <ETag>`: если файл не менялся, сервер отдаёт остаток (`206`),
если его заменили — файл целиком (`200`), и загрузка начинается заново.

Если папка ВидеоТВ недоступна с сервера, `config`, `music` и `ads` отвечают `503`, а не пустым списком:
по пустому списку приставка удалила бы свой кэш. На `503` и любые ошибки, кроме 404 с кодом
`device_not_registered`, приложение продолжает играть то, что уже скачано.

Все `url` в ответах — пути от корня сервера (`/api/video-device/...`), уже закодированные.
Приставка дописывает их к адресу портала и передаёт тот же заголовок с ключом.

**Адреса портала.** В APK зашиты основной адрес (`videoPortalUrl`, сейчас `https://office.ludilove.ru`) и запасные
(`videoPortalBackupUrls`, сейчас `https://portal.ludilove.ru`). На запасной приложение переходит само, если основной
недоступен (DNS, сертификат, таймаут) или ответил не как этот API — то есть не JSON (страница IIS, другой сайт).
Ответ самого API, даже ошибка (`401`, `404 device_not_registered`), окончательный. Основной после сбоя пробуется
снова раз в час. Поэтому при смене имени портала достаточно, чтобы новый портал отвечал на любом из этих имён
(привязка в IIS + сертификат); обновлять приставки не нужно. Все ответы API, включая ошибки, — JSON с полем `message`:
по этому приложение отличает его от чужих страниц.

## `config`

```json
{
  "mode": "video",
  "muteStartTime": "23:10",
  "muteEndTime": "07:50",
  "videos": [
    { "name": "TV1_06112026.mp4", "available": true, "sizeBytes": 52428800, "url": "/api/video-device/videos/TV1_06112026.mp4" },
    { "name": "Старое.mp4", "available": false, "sizeBytes": 0, "url": "/api/video-device/videos/%D0%A1..." }
  ],
  "missingVideos": ["Старое.mp4"]
}
```

- `mode` — `"video"` или `"music"`. Смешанного режима больше нет (старое значение `OnlyMusic = 0` отдаётся как `"video"`).
- `muteStartTime`/`muteEndTime` — `ЧЧ:ММ` или `null` (тогда приложение берёт значения по умолчанию).
- `videos` — все видео из настроек в заданном порядке. `available: false` — файла сейчас нет в папке:
  приложение его не качает, но уже скачанную копию не удаляет и показывает.
- `sizeBytes` — точный размер; если локальный файл другого размера (файл заменили с тем же именем), приложение перекачивает его.
- `missingVideos` — имена с `available: false`. Только для диагностики.

## `music` и `ads`

```json
[ { "name": "Трек", "fileName": "Трек.mp3", "sizeBytes": 5721166, "url": "/api/video-device/audio?path=%D0%9C..." } ]
```

`sizeBytes` — точный размер: локальная копия другого размера (недокачанная или испорченная) перекачивается.
`fileName` уникален в пределах ответа: если в подпапках есть одноимённые файлы, остаётся первый.

## `heartbeat`

Приложение 2.0+ раз в 2 минуты (первый раз — через 15 секунд после запуска) отправляет:

```json
{
  "ip": "10.140.54.60:8080",
  "appVersion": "2.0",
  "mode": "video",
  "isPlaying": true,
  "muted": false,
  "currentFile": "TV1_90_06112026.mp4",
  "lastConfigOkSecondsAgo": 1200,
  "lastError": null,
  "itemsReady": 1,
  "itemsTotal": 1,
  "brokenItems": 0,
  "freeSpaceMb": 5120,
  "uptimeSeconds": 86400,
  "deviceTimeMs": 1794901350709,
  "bootUptimeSeconds": 259200,
  "networkType": "ethernet",
  "wifiRssi": null,
  "downloadKbps": 5300,
  "hdmiConnected": true,
  "ramFreeMb": 812,
  "cpuTempC": 55
}
```

Поля диагностики (все необязательные; чего прошивка не даёт, то `null`):
`deviceTimeMs` — часы приставки (сервер считает расхождение со своими), `bootUptimeSeconds` — сколько работает
с включения (по нему видно перезагрузки), `networkType` — `ethernet`/`wifi`/`other`/`none`, `wifiRssi` — сигнал Wi-Fi
в дБм, `downloadKbps` — скорость последнего скачивания крупного файла, `hdmiConnected` — подключён ли экран,
`ramFreeMb`, `cpuTempC`, `portalHost` — адрес портала, на который ходит приставка (основной или запасной; сам портал
за прокси его не видит), `volumePercent` и `systemMuted` — громкость музыки в системе приставки, `audioOutput` —
куда идёт звук (`line` — колонки, `hdmi` — телевизор, `default`), `stalledSeconds` — сколько воспроизведение стоит
на месте (присылается от 30 с), `freezesLastHour` — сколько раз за час приложение перезапускало зависший плеер
(перезапуск — после минуты без движения). Первый сигнал после обрыва связи добавляет `outageSeconds` и
`outagePlayingPercent` — сколько не было связи и какую долю этого времени шёл контент. Адрес портала, на который пришёл сигнал (основной или запасной), сервер берёт из самого запроса.

Сервер хранит последний сигнал в отдельной таблице `OfficeVideoDeviceHeartbeats` (создаётся при старте портала;
`VideoDevices`, общую со старым порталом, не трогаем), время берёт по своим часам и обновляет версию приставки.
Неизвестная приставка получает тот же `404` с кодом `device_not_registered`.

Статус в админке (`GET /api/VideoDevices/devices/presence`, страница обновляет его раз в минуту):

- `playing` — сигнал моложе 5 минут, контент идёт, всё скачано, настройки свежие;
- `problem` — сигнал есть, но экран пустой, скачано не всё, есть сломанные файлы или настройки не обновлялись больше 3 часов;
- `offline` — сигнала нет дольше `VideoDevices:HeartbeatOfflineMinutes` (по умолчанию 5).

Проблемы (переводят в `problem`) делятся на два уровня (`severity`), красные идут в `problems` первыми:

- `critical` (красный — контент не доходит до зрителя): экран пустой или музыка не играет; воспроизведение стоит
  30 с и больше; HDMI не подключён (видео); в музыке (кроме тишины по расписанию) — громкость 0 или звук выключен,
  звук идёт в HDMI без телевизора; свободного места меньше 300 МБ. Без связи — если перед пропажей уже была
  проблема или связи нет дольше `VideoDevices:OfflineAttentionHours` (сутки).
- `warning` (жёлтый — работает, но деградирует): места меньше 1 ГБ; скачано не всё дольше 2 часов (раньше — замечание
  «идёт загрузка», портал помнит начало в `IncompleteSinceUtc`); битые файлы — в видео любые, в музыке от 10 треков
  или 5% библиотеки; настройки не обновлялись больше 3 часов; часы расходятся на 5 минут и больше; плеер зависал
  3 и больше раз за час; температура от 90 °C.

Замечания (`notices`, на статус не влияют): недокачка первые 2 часа, несколько битых треков в музыке, HDMI не
подключён в режиме музыки, громкость музыки ниже 20%, нет root и прав владельца, плеер зависал 1–2 раза за час,
температура 80–89 °C, Wi-Fi слабее −75 дБм, приставка включилась меньше 30 минут назад, недавний обрыв связи
с итогом «шёл ли контент» (сутки после восстановления).

## Команды на приставку (порт 8080)

Админка (`POST /api/VideoDevices/devices/command` с `{ ip, command, fileName? }`) передаёт их на приставку
с тем же заголовком `X-Device-Key`; без верного ключа приложение отвечает `401` и ничего не делает.
Ответ приставки — JSON `{ ok, message }`.

| `action` | Что делает |
|---|---|
| `sync` | получает настройки и докачивает недостающее сразу, без случайной задержки фоновой загрузки |
| `redownload&param1=<имя файла>` | удаляет свою копию файла (видео, музыка или реклама) и скачивает заново; `404`, если такого нет |
| `reboot` | перезагружает приставку (`su -c reboot`) через секунду после ответа |
| `volume&param1=<0–100>` | ставит системную громкость музыки и отвечает фактическим значением (`Громкость 53%`): шаги у приставок разные |
| `update&param1=<имя APK>` | скачивает APK с портала (`apk?name=`), проверяет, что это то же приложение с той же подписью, ставит через `su pm install -r -d`; новая версия запускается сама (`MY_PACKAGE_REPLACED`). Ответ — «принято»; успех админка видит по сигналу новой версии (приложение запущено после команды), ошибка приходит в `lastError` как «Обновление (…) не удалось: …» |

| `owner-release` | снимает права владельца устройства (см. ниже); на прошивках без телефонии (X96Q) Android падает — приставка отвечает ошибкой |

**Права приставки.** В сигнале `hasRoot` (есть `su`) и `deviceOwner` (приложение — владелец устройства). `update`
и `reboot` работают при любом из них; скриншот — только с root. Без обоих `reboot` отвечает `501` (а не ложным
«перезагружается»), `update` — ошибкой, а админка обновляет такую приставку через ADB, как 1.9.
Права владельца выдаются один раз через ADB (`POST /api/VideoDevices/devices/grant-owner`, по сути
`dpm set-device-owner com.example.video/.admin.VideoDeviceAdminReceiver`). Android откажет, если на приставке есть
аккаунты или прошивка не поддерживает `android.software.device_admin` (так у части X96Q). Снять права на прошивках
без телефонии можно только через root (удалить `/data/system/device_owner_2.xml` и `device_policies.xml`,
перезагрузить) или сбросом; пока права есть, приложение нельзя удалить.

Старое приложение этих команд не знает и отвечает `400 Unknown action`: админка предлагает обновить его.

Приставки со старым приложением сигналов не шлют: для них по-прежнему работает только проверка через порт 8080.
