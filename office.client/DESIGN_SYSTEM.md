# Дизайн-система корпоративного портала Office

Версия: 1.4
Статус: обязательная спецификация для новых интерфейсов и изменений существующих экранов.

## 1. Назначение

Этот документ — единый источник визуальных и UX-правил клиентской части Office. Он нужен, чтобы разделы портала выглядели как один продукт независимо от автора и даты реализации.

Кодовые источники токенов:

- `src/styles/design-tokens.css` — типографика, размеры, радиусы, отступы и тени;
- `src/styles/color-inventory.css` — семантические цвета светлой и тёмной тем;
- `src/App/App.css` — глобальное применение шрифтов и базовые правила приложения;
- `src/Components` — переиспользуемые контролы.

Если документ и реализация временно расходятся, новое решение проектируется по документу, а недостающий токен добавляется в общий файл токенов. Локальные «почти такие же» значения не создаются.

## 2. Принципы

1. **Рабочий интерфейс важнее декора.** Портал плотный, быстрый и спокойный. Декор не должен уменьшать полезную площадь.
2. **Один паттерн — один компонент.** Поле, селект, чекбокс, модалка или состояние загрузки не рисуются заново внутри страницы.
3. **Смысл задаётся токеном.** В компонентах используются `--color-text`, `--color-border`, `--color-primary`, а не конкретные HEX-цвета.
4. **Иерархия строится размером и начертанием.** Капс и яркий цвет применяются точечно.
5. **Интерфейс не прыгает.** Hover не меняет геометрию карточки, строки или кнопки.
6. **Мобильная версия — самостоятельная компоновка.** Это не уменьшенная десктопная страница.
7. **Тёмная тема обязательна.** Компонент считается завершённым только после проверки в обеих темах.
8. **Состояние всегда объяснимо.** Загрузка, пустой результат, ошибка, disabled и успешное действие имеют явную обратную связь.
9. **Одинаковая информационная архитектура использует один шаблон.** Схожие каталоги и рабочие панели не копируют локально toolbar, метрики, фильтры и карточки: они подключают общий `entity-dashboard.module.css` или соответствующий общий компонент. Отличается содержимое и бизнес-логика, но не геометрия и визуальный язык.

## 3. Типографика

### 3.1. Шрифтовые роли

| Роль | Шрифт | Применение |
|---|---|---|
| Основной | Roboto Condensed Variable | Текст, формы, таблицы, кнопки, подсказки, значения |
| Акцентный | Akrobat | Заголовки, названия разделов, навигация, полностью прописные подписи |
| Моноширинный | системный monospace | Код, технические идентификаторы, логи |

Токены:

```css
font-family: var(--font-body);
font-family: var(--font-heading);
font-family: var(--font-uppercase);
font-family: var(--font-mono);
```

Правила:

- основной вес текста — `350`;
- обычное смысловое выделение — `500`;
- `600–700` допустимы для кнопок, заголовков карточек и важных значений;
- Akrobat используется для `h1–h6`, заголовков модалок, названий разделов, левого меню и элементов с `text-transform: uppercase`;
- аббревиатура внутри обычной строки (`ТТ`, `PDF`, `RK`) не переводит всю строку в Akrobat;
- основной текст не получает отрицательный `letter-spacing`;
- для капса допустим `letter-spacing: 0.04em–0.08em`, для крупных заголовков — `normal`;
- не использовать вес `800–900` в основном тексте.

### 3.2. Типографическая шкала

| Стиль | Размер / строка | Вес | Шрифт |
|---|---:|---:|---|
| Заголовок страницы | `28 / 32` | 600 | Akrobat |
| Заголовок раздела | `24 / 28` | 600 | Akrobat |
| Заголовок модалки | `18 / 24` | 600 | Akrobat |
| Заголовок карточки | `16 / 20` | 600 | Akrobat или Roboto Condensed |
| Основной текст | `16 / 22` | 350 | Roboto Condensed |
| Компактный текст | `14 / 20` | 350 | Roboto Condensed |
| Подпись поля | `14 / 18` | 500 | Roboto Condensed |
| Вспомогательный текст | `12 / 16` | 350 | Roboto Condensed |
| Служебный капс | `11–12 / 16` | 700 | Akrobat |

На телефоне заголовок страницы уменьшается до `22–24px`, основной текст остаётся не меньше `14px`. Интерактивный текст меньше `14px` не используется.

## 4. Цветовая система

### 4.1. Семантические цвета

Компоненты используют только семантические токены.

| Назначение | Токен |
|---|---|
| Главный фон страницы | `--color-bg` |
| Фон карточек, форм и модалок | `--color-surface` |
| Вторичный фон | `--color-surface-muted` |
| Основной текст | `--color-text` |
| Вторичный текст | `--color-text-muted` |
| Слабый текст / placeholder | `--color-text-subtle` |
| Обычная граница | `--color-border` |
| Усиленная граница | `--color-border-strong` |
| Главное действие | `--color-primary` |
| Hover главного действия | `--color-primary-hover` |
| Фирменная заливка кнопки | `--color-primary-solid` |
| Текст на фирменном фоне | `--color-on-primary` |
| Контрастный текст на фирменной заливке | `--color-on-primary-solid` |
| Успех | `--color-success` |
| Ошибка / удаление | `--color-danger` |
| Предупреждение | `--color-warning` |
| Информация | `--color-info` |
| Затемнение модалки | `--color-overlay-modal` |

Основной цвет применяется для действий и текущего состояния, но не для больших декоративных областей. На одном экране не должно быть нескольких конкурирующих акцентных цветов.

### 4.2. Контраст

- обычный текст: контраст не ниже `4.5:1`;
- крупный текст и иконки: не ниже `3:1`;
- placeholder не заменяет label;
- цвет не является единственным способом показать ошибку или выбранное состояние;
- фирменные заливки сохраняют оранжевый `#f47920` и используют белый `--color-on-primary-solid`; подписи таких контролов имеют усиленное начертание и не применяются к длинному тексту;
- фирменный цвет не заменяется бордовым или коричневым ради контраста: если обычный текст на заливке читается недостаточно хорошо, выбирается иной паттерн компонента — outline, светлая фирменная поверхность или более крупная подпись;
- `--color-text-subtle` используется для placeholder и второстепенных подписей, но не для основного текста;
- статусная плашка всегда использует согласованную пару `*-bg` + `*-text`, например `--color-success-bg` и `--color-success-text`;
- контраст проверяется в итоговой паре foreground/background, включая hover, disabled и обе темы.

### 4.3. Тёмная тема

- нельзя прописывать локальные `#fff`, `#333`, `#eee` для поверхности, текста и границы;
- тёмная тема меняет значения токенов, а не структуру компонента;
- изображения и логотипы не инвертируются автоматически;
- тени в тёмной теме заменяются границей или более тёмным overlay, если становятся незаметны;
- disabled должен оставаться читаемым, но явно неактивным;
- перед завершением экран проверяется с `data-theme="light"` и `data-theme="dark"`.

## 5. Размеры, отступы и сетка

### 5.1. Базовая сетка

Все расстояния кратны `4px`.

| Токен | Значение | Применение |
|---|---:|---|
| `--space-1` | 4px | микрозазор |
| `--space-2` | 8px | иконка + текст, тесная группа |
| `--space-3` | 12px | внутренний отступ компактного контрола |
| `--space-4` | 16px | стандартный внутренний отступ |
| `--space-5` | 20px | увеличенный отступ внутри составного блока |
| `--space-6` | 24px | разделение смысловых блоков |
| `--space-8` | 32px | крупное разделение на десктопе |
| `--space-10/12/16` | 40/48/64px | редкие крупные layout-интервалы |

### 5.2. Компоновка страницы

- глобальная шапка: `60px`;
- десктопное боковое меню: `250px`, свёрнутое — `60px`;
- служебный footer: `25px`;
- внутренний отступ рабочей страницы: `16px` на десктопе, `12px` на планшете, `8px` на телефоне;
- расстояние между основными блоками: `16px`;
- информационные и каталожные страницы могут ограничивать строку контента, таблицы и рабочие редакторы используют всю доступную ширину;
- вложенные белые панели не создаются без необходимости: если родитель уже является поверхностью, дочерний блок разделяется отступом или границей.

### 5.3. Радиусы

| Токен | Радиус | Назначение |
|---|---:|---|
| `--radius-sm` | 4px | checkbox, маленький badge |
| `--radius-control` | 8px | поле, кнопка, строка, icon button |
| `--radius-card` | 12px | карточка, dropdown, панель |
| `--radius-lg` | 16px | крупная панель, модалка |
| `--radius-pill` | 999px | chip, pill badge |

На одном уровне интерфейса выбирается один радиус. Нельзя смешивать `8`, `9`, `10`, `11` и `12px` у однотипных карточек.

#### Вложенные радиусы

Внутренний радиус определяется геометрически, а не выбирается на глаз:

```text
Rinner = max(0, Router − inset)
inset = padding родителя + толщина его границы
```

| Родитель | Inset до ребёнка | Правильный внутренний радиус |
|---|---:|---:|
| Модалка `16px` | `16px + 1px` | `0px`; вложенная поверхность не скругляется |
| Карточка `12px` | `4px + 1px` | около `8px` |
| Панель `12px` | `8px + 1px` | около `4px` |
| Панель `16px` | `8px + 1px` | около `8px` |

- если ребёнок касается края родителя, он наследует соответствующие внешние углы;
- если inset больше или равен внешнему радиусу, внутреннее скругление не требуется;
- соседние вложенные элементы используют одинаковый радиус;
- формула относится к видимой вложенной поверхности, а не к обычному текстовому контенту.

### 5.4. Размеры контролов

| Токен | Высота | Назначение |
|---|---:|---|
| `--control-height-sm` | 36px | плотная таблица, вторичный desktop-control |
| `--control-height-md` | 40px | стандартная desktop-кнопка |
| `--control-height-lg` | 48px | Input, Select, мобильная кнопка |
| `--touch-target-min` | 44px | минимальная интерактивная зона на touch-экране |

- видимый control может быть `36–40px`, но его интерактивная область на touch-экране должна быть не меньше `44×44px`;
- элементы одной строки формы имеют одинаковую высоту;
- размер не выбирается отдельно на каждой странице: используется один из трёх токенов;
- иконка может быть `20px`, но кнопка вокруг неё — минимум `40px` на desktop и `44px` на touch.

### 5.5. Тени

- `--shadow-sm` — всплывающий акцент или интерактивная карточка;
- `--shadow-md` — dropdown и закреплённая панель;
- `--shadow-lg` — модалка;
- обычные рабочие карточки преимущественно отделяются границей, а не тенью;
- не создавать собственные `box-shadow`, если подходит системный токен.

## 6. Иконки

- базовый набор — `@mui/icons-material` и утверждённые SVG проекта;
- размер внутри строки — `18–20px`;
- стандартная кнопка-иконка — иконка `20–24px`, зона нажатия `40×40px` на desktop и минимум `44×44px` на touch;
- крупное состояние страницы — `48–64px`;
- иконка дополняет текст, если значение действия не очевидно;
- у кнопки только с иконкой обязательны `aria-label` и tooltip;
- не смешивать outline и filled-иконки внутри одной группы действий без смысловой причины.

## 7. Компоненты

Для нового кода используются компоненты из `src/Components`. Нативные аналоги допустимы только внутри реализации этих компонентов или в случае доказанного ограничения.

### 7.1. Кнопки

Варианты: Primary — главное действие; Secondary — нейтральное альтернативное; Ghost — малозаметное; Danger — необратимое; Icon — компактное действие.

- стандартная высота — `var(--control-height-md)`, мобильная или крупная — `var(--control-height-lg)`;
- горизонтальный padding — `16px`, gap иконки и текста — `8px`;
- радиус — `var(--radius-control)`;
- в одном блоке только одна Primary-кнопка;
- порядок справа налево: главное действие, вторичное действие; destructive-действие отделяется;
- disabled не реагирует на hover и не меняет курсор на pointer;
- hover меняет цвет или границу, но не использует `scale` и не сдвигает элемент;
- во время сохранения кнопка блокируется и показывает процесс без изменения ширины.

### 7.2. Поля ввода

Канонический компонент: `Components/Input`.

- стандартная высота — `var(--control-height-lg)`; компактный desktop-вариант — `var(--control-height-md)`;
- размер текста — `16px`;
- label видим всегда;
- focus у полей формы отображается одним непрерывным акцентным контуром: компоненты не должны одновременно рисовать собственные `border`/`box-shadow` и глобальный внешний `outline`;
- ошибка: красная граница, иконка при необходимости и текст под полем;
- helper/error text — `12–14px`;
- disabled использует семантические surface/text-токены;
- placeholder — пример или подсказка, а не название поля.

### 7.3. Select

Канонический компонент: `Components/Select`.

- внешний вид и высота совпадают с Input;
- для списка более 10 элементов включается `search`;
- dropdown рендерится поверх контента, не обрезается родительским `overflow`;
- высота списка ограничена, прокрутка находится внутри списка;
- выбранное значение видно после повторного открытия;
- пустое состояние: «Ничего не найдено»;
- множественный выбор реализуется через `MultiplySelect`, а не отдельный локальный dropdown.

### 7.4. Checkbox и Toggle

Канонические компоненты: `Components/Checkbox` и `Components/Toggle`.

- checkbox — выбор одного или нескольких независимых значений;
- toggle — немедленное включение состояния;
- checkbox не заменяется символом или самописным квадратом;
- label кликабелен вместе с контролом;
- размер checkbox: `18px` в плотном списке, `24px` в обычной форме;
- у disabled должно быть понятно, почему действие недоступно; при необходимости добавляется tooltip.

### 7.5. Карточки

- фон `--color-surface`;
- граница `1px solid var(--color-border)`;
- радиус `var(--radius-card)`;
- padding `12px` для компактной и `16px` для обычной карточки;
- заголовок и основное действие находятся в предсказуемых местах;
- описание отображается, если оно введено и помогает отличить объект;
- hover меняет фон или границу; карточка не поднимается и не масштабируется;
- вся карточка кликабельна только при одном основном действии;
- кнопки внутри карточки не запускают переход карточки;
- статус размещается рядом с названием или в стабильном углу, а не поверх изображения без причины.

### 7.6. Модалки

Канонический компонент: `Components/Modal`.

| Размер | Максимальная ширина | Назначение |
|---|---:|---|
| `sm` | 420px | подтверждение, короткая форма |
| `md` | 720px | стандартная форма |
| `lg` | 1024px | сложный редактор |
| Viewer | до 96vw | PDF, видео, офисные документы |

- максимальная высота — `90dvh`, body прокручивается независимо;
- header и footer остаются видимыми;
- заголовок — Akrobat `18/24`, вес 600;
- кнопка закрытия `40×40px` на desktop и минимум `44×44px` на touch, доступна при любом размере экрана;
- Escape закрывает модалку, фокус возвращается к вызвавшему элементу;
- backdrop блокирует прокрутку страницы;
- на телефоне модалка имеет отступ `8px`, `max-height: calc(100dvh - 16px)`;
- viewer на телефоне может занимать весь экран, но его кнопка закрытия всегда находится в safe area;
- footer: Secondary слева от Primary; удаление отделено от сохранения.

### 7.7. Таблицы

Канонический компонент: `Components/GenericTable`.

| Плотность | Высота строки |
|---|---:|
| Компактно | 40px |
| Обычно | 48px |
| Комфортно | 56px |

- числовые значения выравниваются вправо, текст — влево;
- действия строки находятся в последнем столбце;
- сортировка и фильтр имеют видимое активное состояние;
- текст обрезается с ellipsis и раскрывается через title/tooltip;
- горизонтальная прокрутка допустима для широкой служебной таблицы;
- на телефоне приоритетные столбцы остаются видимыми, остальные скрываются или строка превращается в карточку;
- настройки таблицы используют единую модалку/панель и не перекрывают вызвавшую кнопку.

### 7.8. Навигация и вкладки

- глобальная шапка и боковое меню имеют высоту шага `60px`;
- выбранный пункт отмечается акцентной полосой или цветом;
- названия пунктов бокового меню — Akrobat;
- вкладки — Akrobat и прописные буквы;
- активная вкладка имеет фон/нижнюю границу, неактивная остаётся нейтральной;
- хлебные крошки показывают реальный путь, имеют вертикальный padding и горизонтальную прокрутку на телефоне;
- кнопка «Назад» не дублируется одновременно в глобальной и локальной шапке без причины.

### 7.9. Badge и chip

- badge описывает статус, chip — выбранный фильтр или компактную сущность;
- высота `24px` или `28px`, padding по горизонтали `8px` или `12px`;
- текст `12–14px`, вес `500–600`;
- цвет статуса семантический;
- не показывать технические статусы вроде «Готово», если они не помогают принять решение.

## 8. Состояния интерфейса

### Загрузка

- состояние размещается по центру доступной рабочей области, а не всего viewport поверх навигации;
- используется общий `LoadingSpinner` и только три системных размера: `24px` в кнопке, `56px` внутри блока и `96px` для страницы;
- значения до `34px` автоматически используют упрощённый вариант без мелких эффектов;
- загрузчик появляется с задержкой `220ms`, чтобы быстрый запрос не создавал мелькание, а при замене страницы контентом исчезает за `180ms`;
- страничная и крупная блочная загрузка получает короткий текст через `label`, например «Загружаем стоп-листы…»; через 6 секунд текст меняется на «Почти готово…»;
- цвет выпечки остаётся натуральным в обеих темах; акцент темы применяется только к служебной анимации;
- `prefers-reduced-motion` заменяет сюжет статичным изображением хлеба;
- существующий контент не очищается при фоновом обновлении без необходимости.

### Пустое состояние

- крупная иконка, короткий заголовок, одно пояснение;
- действие показывается только если пользователь действительно может исправить ситуацию;
- «Ничего не найдено» для поиска отличается от «Данных пока нет».

### Ошибка

- состояние центрируется аналогично загрузке;
- содержит понятный заголовок, человеческое описание и кнопку «Повторить»;
- технический HTTP-текст не показывается пользователю;
- подробность записывается в лог сервера или консоль разработки.

### Disabled и read-only

- disabled означает невозможность взаимодействия;
- read-only означает доступное для копирования значение без редактирования;
- если запрет зависит от роли или данных, причина доступна через подпись или tooltip.

## 9. Адаптивность

| Диапазон | Назначение |
|---|---|
| `> 1200px` | широкий рабочий экран |
| `901–1200px` | компактный десктоп / планшет landscape |
| `641–900px` | планшет |
| `≤ 640px` | телефон |
| `≤ 390px` | узкий телефон, финальная проверка |

Правила телефона:

- контент не создаёт горизонтальный scroll страницы;
- целевой размер зоны касания — не меньше `44×44px`; абсолютный минимум WCAG 2.2 AA — `24×24px` или эквивалентный безопасный интервал;
- формы становятся одноколоночными;
- панели действий закрепляются снизу только если не перекрывают контент и учитывают safe area;
- длинные заголовки используют ellipsis или переносятся, но не выталкивают кнопки;
- таблицы адаптируются осознанно, а не просто уменьшают шрифт;
- модалка и viewer всегда позволяют закрытие без прокрутки до кнопки;
- проверка проводится минимум на ширинах `390px`, `430px`, `640px`, `900px`.

```css
padding-bottom: max(var(--space-3), env(safe-area-inset-bottom));
```

## 10. Motion

- быстрый hover/focus: `120–160ms`;
- dropdown, панель и модалка: `180–240ms`;
- easing по умолчанию: `ease`;
- анимируются `opacity`, `color`, `background-color`, `border-color`, иногда `transform` у оверлеев;
- карточки, замки и строки не используют `scale` на hover;
- анимация не должна менять layout;
- учитывается `prefers-reduced-motion: reduce`.

## 11. Слои

| Слой | Рекомендуемый z-index |
|---|---:|
| Обычный контент | 0 |
| Sticky header / footer | 10–20 |
| Dropdown / tooltip | 100–200 |
| Модалка | 1000 |
| Dropdown внутри портальной модалки | 2000 |
| Критическое системное сообщение | 3000 |

Новый `z-index` выше этих значений добавляется только после проверки владельца слоя.

## 12. Доступность

- весь интерфейс управляется клавиатурой;
- focus-visible нельзя отключать без равноценной замены: базовый индикатор — сплошной outline `2px` с offset `2px` и контрастом изменения не ниже `3:1`;
- sticky-панели и модалки не должны полностью перекрывать элемент с keyboard focus;
- иконки-кнопки имеют доступное имя;
- поля связаны с label;
- модалка использует `role="dialog"` и `aria-modal="true"`;
- ошибки формы связаны с полями через `aria-describedby`;
- состояние определяется не только цветом;
- декоративные изображения имеют пустой `alt`, смысловые — описательный;
- уведомления о результате операции доступны screen reader через live region.

## 13. Правила CSS и React

### Обязательно

- CSS Modules для локальных стилей;
- глобальные правила только в `App.css` и `src/styles`;
- цвет, шрифт, радиус, тень и повторяемый отступ берутся из токенов;
- повторяемый UI выносится в `src/Components`;
- состояния оформляются через класс или `data-*`, а не цепочку inline-style;
- компонент проверяется в обеих темах и на телефоне.

### Запрещено в новом коде

- hardcoded HEX/RGB/HSL для системных цветов;
- новый checkbox, toggle, select или modal внутри страницы;
- `transition: all`;
- hover через `scale` или сдвиг рабочей карточки;
- произвольные радиусы для однотипных компонентов;
- отрицательные margin для исправления базовой компоновки;
- `100vh` в мобильных полноэкранных элементах — используется `100dvh`;
- уменьшение текста ниже 12px ради размещения контента;
- глобальный селектор из CSS Module;
- `!important`, кроме интеграции со сторонней библиотекой с поясняющим комментарием.

- [ ] длинные русские названия не ломают layout;
- [ ] сборка и профильные тесты проходят.

## 16. Статус миграции и допустимые исключения

Базовая миграция выполнена для всего `src`: системные цвета вынесены в палитру, размеры текста не опускаются ниже 12px, отступы следуют 4px-сетке, радиусы нормализованы, `transition: all` и меняющие геометрию hover-эффекты удалены. Общие Input, Select, Checkbox, Toggle, Button и Modal являются исходной точкой для новых интерфейсов.

`npm run design:audit` контролирует эти правила автоматически. Изменение считается незавершённым, если аудит, сборка или тесты не проходят.

Осознанные исключения:

- Office Viewer воспроизводит размеры, цвета и геометрию исходного документа; контентные метрики документа не подчиняются UI-сетке;
- экспортируемый Excel использует стабильную светлую документную палитру независимо от темы портала;
- `!important` допустим только на границе со сторонним компонентом, для глобального typography/reduced-motion override или полноэкранного мобильного слоя; новый случай сопровождается комментарием `design-system-exception`;
- SVG- и canvas-рендереры, которые не умеют читать CSS custom properties, получают вычисленные значения семантических токенов из TypeScript;
- визуально скрытый нативный control может использовать отрицательный отступ как часть доступного custom-control паттерна.

При работе над экраном исправляется весь затронутый паттерн, а не только один заметный элемент. Временные локальные вариации не создаются.

## 17. Текст, данные и локализация

- интерфейс говорит действием: «Сохранить», «Повторить», «Выбрать торговую точку»; неоднозначные «ОК» и «Да» допустимы только в очевидном подтверждении;
- заголовок сообщает объект или задачу, описание — следующее полезное действие, а не повтор заголовка;
- ошибки объясняют, что произошло и что может сделать пользователь; внутренние коды и stack trace в UI не выводятся;
- даты отображаются в локали пользователя, для текущего портала — `dd.MM.yyyy`; время явно использует московскую зону там, где это бизнес-правило;
- числа, валюты и единицы форматируются через `Intl`, а не конкатенацией строк;
- технические ID не заменяют понятное название сущности;
- значения, которые могут быть длинными, проверяются минимум на 80 символах; для однострочного контента используется ellipsis с доступом к полному значению;
- текст интерфейса не встраивается в CSS через `content`, кроме декоративных символов;
- layout не зависит от конкретной длины русского текста и готов к увеличению подписи примерно на 30%.

## 18. Формы и валидация

- обязательность поля указана до отправки формы и доступна не только по цвету;
- валидация запускается после взаимодействия с полем или отправки, но не показывает ошибку при первом открытии пустой формы;
- сообщение находится рядом с полем, связано через `aria-describedby` и сохраняется до исправления;
- введённые корректные данные не очищаются после ошибки запроса;
- основное действие формы блокируется только если повторная отправка опасна или запрос уже выполняется;
- Enter отправляет простую форму, Escape закрывает временный слой, если это не приведёт к потере несохранённых данных без подтверждения;
- сервер остаётся источником истины для прав и бизнес-валидации; frontend-проверка нужна для быстрой обратной связи, но не заменяет backend.

## 19. Производительность и устойчивость

- страницы и тяжёлые viewer-компоненты загружаются лениво;
- изображения задают размеры или `aspect-ratio`, чтобы не вызывать скачок layout;
- большие списки не рендерятся без пагинации, виртуализации или обоснованного лимита;
- background refresh сохраняет текущие данные и показывает ненавязчивый progress;
- skeleton повторяет итоговую геометрию; бесконечный spinner без текста не используется для загрузки страницы;
- сетевые ошибки имеют retry, отменённый запрос не показывается как ошибка пользователя;
- минимально поддерживаемые браузеры определяются настройкой сборки; используются progressive enhancement и feature queries для необязательных возможностей.

## 20. Управление системой

- изменение существующего токена предпочтительнее добавления почти идентичного;
- новый токен получает семантическое имя, описание назначения и значения обеих тем;
- удаление или изменение смысла токена считается breaking change и проводится вместе с миграцией всех потребителей;
- временное исключение содержит комментарий `design-system-exception`, причину, владельца и условие удаления;
- `npm run design:audit` проверяет запрещённые CSS-паттерны во всём `src`;
- визуально значимые общие компоненты проверяются snapshot/regression-тестом на светлой и тёмной темах, desktop и ширине `390px`;
- документ, токены и компоненты меняются в одном pull request, если меняется публичный контракт системы.

### Матрица обязательных состояний компонента

Каждый интерактивный компонент проверяется в состояниях: default, hover, focus-visible, active, disabled, loading, error (если применимо), тёмная тема и touch. Для контейнеров дополнительно проверяются empty, overflow и длинный контент.

Все текстовые действия — в том числе «Сохранить», «Отмена», «Удалить», «Добавить» и «Повторить» — реализуются через `Components/Button/Button`. CSS страницы управляет только расположением такой кнопки (`margin`, `width`, размещение в grid/flex), но не переопределяет её цвет, высоту, padding, радиус или типографику. Локальные классы наподобие `.saveButton`, `.cancelButton` и `.primaryButton` на нативном `<button>` запрещены автоматическим аудитом.

### Контроль перед выпуском

1. `npm run design:audit`;
2. `npm run build`;
3. `npm test`;
4. ручная проверка основных маршрутов в обеих темах на `390`, `640`, `900` и широком desktop;
5. keyboard-only проход по формам, dropdown и модалкам;
6. проверка контраста итоговых foreground/background пар, а не только значений токенов.
